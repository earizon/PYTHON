# Virtual environments

* A virtual environment in Python usually refers to the capacity to install different sets of libraries in parallel.


As of 2025 virtual enviroment alternatives include:


- uv:  Rust based, 10-100x faster than pip.
  - Includes pip-compatible interface.
  - Single tool replacing pip, pip-tools, pipx, poetry, pyenv, twine, virtualenv, and more.
  - Provides comprehensive project management, with a universal lockfile.
  - Runs scripts, with support for inline dependency metadata.
  - Installs and manages Python versions (replacing pyenv).
  - Runs and installs tools published as Python packages.
  - Supports Cargo-style workspaces for scalable projects.
  - Disk-space efficient, with a global cache for dependency deduplication.
  - Installable without Rust or Python via curl or pip.
  - Supports macOS, Linux, and Windows.

- pip + venv:<br/>
  **WARN**: Never use pip alone (without venv) in Linux based systems, since
  python itself is used for administration tasks, and you can break
  the OS itself. [[PM.risk,doc_has.keypoint]]
  ```
  $ cd ${MY_PROJECT}
  $ python3 -m venv .venv $ # create new virtual environment in ${MY_PROJECT}/.venv directory
  $ . .venv/bin/activate
  $ ...
  ```
- pipenv:<br/>
  - pipenv makes a few things simpler, but ... "for every thing it simplifies, 
    it makes other things more complex than they need to be."
- pyenv (Outdated by uv), not to be confused with pipenv:<br/>
  pyenv  allows to run install different versions of Python (python 3.7, 3.10, 3.14) in parallel on the same system 
  and switch among them. (Not needed with `uv`).
- conda:<br/>
  - Similar to pip + venv, but it replaces the official PyPA repositories with custom ones
    maintained by Anaconda and focusing in making the Scikit and ML stack work together.
    (Numpy/Pandas, PyTorch, TensorFlow, ...)
    more stability for the python science packages (but it probably misses new packages)
