# Python Modules and Packages

* REF: <https://docs.python.org/3/tutorial/modules.html>
* REF: <https://docs.python.org/3/tutorial/modules.html#packages>

* Modules  isolate collading global variables names on different (*py) modules.
* Packages isolate modules names in different package namespaces
  Two packages like NumPy and Pillow both can have a module with the
  same name without any collision.

* Example package+module layout:

  ```
  | sound/            <·· "sound"                 package (name)         ⁵
  | ├ __init__.py     <·· "sound"                 package initialization ¹
  | ├ formats/        <·· "sound.formats"         
  | · ├ __init__.py   <·· "sound.formats"         package initialization ¹
  | · ├ wavread.py    <·· "sound.formats.wavread" module                 ⁰⁴
  |   ├ ··                                                
  | · ├ ...
  | ├ effects/        <·· "sound.effects" 
  | · ├ __init__.py   <·· "sound.effects"         package initialization ³
  | · │ 
  | · ├ echo.py ²     <·· echo                    module                 ⁰⁴
  | · ├ ...
  | ├ ...
  |
  | ⁰ a *.py file is actually a python module, ie. an isolated namespace.
  |   global symbols do not collide with same name symbols in other *py modules
  |   when imported.
  |   It contains global variables, function definitions and executable code.
  |   intended to initialize the module when imported or executed as entry
  |   point (main script).
  |   NOTE: Other modules can still modify imported module's global variables
  |         unless the name start with the prefix `_`, but this `_` ussage
  |         is discouraged since it introduces an unknown set of names into
  |         the interpreter, possibly causing problems [[qa.best_patterns]]
  |
  |   **each module is only imported once per interpreter session**
  |
  |   SEARCH PATH ORDER FOR MODULES:
  |   1. built-in module with matching name.
  |       (modules listed in sys.builtin_module_names)
  |   2. Search in `sys.path` env.var.
  |      sys.path is initialized from:
  |        directory containing input script 
  |        (WARN: overloading anything in standard lib)
  |      + PYTHONPATH
  |      + installation-dependent default 
  |        (by convention including a "site-packages"
  |         directory handled by the site module).
  |      (sys.path can be modified at runtime)
  |
  |   py files are "zipped" to .pyc and placed in the 
  |   __pycache__/moduleA.cpython-33.pyc,
  |                                  └─┴ Arch.independent format
  |                                      The code continues to be interpreted
  |                                      (vs compiled)
  |               ·     · └────────┴─ ·· python version used
  |               ·     ·                allows for different versions
  |               ·     ·                to coexists.
  |               └─────┴─ ············· module name
  |
  |   Cache is never using when loading the module as an script
  |   invoked from the OS or there is no source module (pyc file
  |   instead of py in source directory)
  |
  | ¹ * __init__.py is required to make Python treat directories containing
  |     the file as packages (unless using a namespace package, a relatively
  |     advanced feature). 
  |      This prevents directories with a common name (eg. `string`, from
  |     unintentionally hiding valid modules that occur later on the module
  |     search path.
  |   * __init__.py can be an emtpy file, but it can also execute initialization 
  |     code for the package at "import" time and/or set the `__all__` variable.
  |
  | ² `import sound.effects.echo` will trigger a search through `sys.path` looking
  |   for the `sound.effects` subdirectory, and once found it will load the
  |   echo module.
  |   Load alternatives include:
  |   import sound.effects.echo                 ··> sound.effects.echo.echofilter(...)
  |   from sound.effects import echo            ··>               echo.echofilter(...)
  |   from sound.effects.echo import echofilter ··>                    echofilter(...)
  |   └─────────────────┬─────────────────────┘
  |   import can import a subpackage, a module or 
  |   element inside the module.
  |
  | ³ cat  sound/effects/__init__.py
  |   __all__ = ["echo", "surround", "reverse"]
  |   ^     ^  
  |   └──┬──┘
  |   Use case:
  |   By convention when trying to do something like `from sound import *`  (import
  |   all submodules in a (sub)package, the `__all__` indicates which modules to
  |   load to avoid undesired effects and maybe long load times.
  |   In general is better not to autoimport all subpackages, since local colliding
  |   names in functions will overwrite the module name, breaking the desired 
  |   namespace safeties.
  |   WARN: Using `*` in imports is considered a bad practice [[qa.best_patterns]]
  |
  |   NOTE: sibling modules/subpackages can use absolute or relative paths to 
  |         refer to other sibling subpackages, but only absolute if intended to
  |         be used as main modules (main entry points to apps).
  |
  | ⁴ Core modules are pre-packaged and are OS dependent.
  |
  |   import fibo
  |   dir(fibo)                 # <·· inspect functions,... defined in module
  |   ['__name__', 'fib', 'fib2']
  |   
  |   dir()            # <·· list current symbols
  |   import builtins  # <·· list builtin functions like:                
  |   dir(builtins)    #     ['ArithmeticError', 'AssertionError',..]
  | 
  |   import sys       # sys module deserves special attention
  |
  |   - sys.ps1, sys.ps2 define the interactive prompt symbols.
  |   - sys.path: interpreter's search path list for modules.
  |     (PYTHONPATH + ...)
  |     sys.path.append('./plugins/pluginA') # runtime tunning
  |
  |  ⁵ package names will be renormalized following the rule:
  |    normalized_form=re.sub(r"[-_.]+", "-", name).lower()
  |    REF: <https://packaging.python.org/en/latest/specifications/name-normalization/>
  |  
  |  Ex: Input pckg name  Normalized form
  |      ---------------  ---------------                          
  |      FRIENDLY-BARD    friendly-bard
  |      Friendly-Bard
  |      friendly.bard
  |      friendly_bard
  |      ...

  ```

  ```
  | def custom_init():
  |  import random                  # <·· imports can go inside functions
  |                                 #     alt: from random import andint
  |  print(random.randint(1, 10))
  |  del random                     # <·· remove module when not needed
  |                                 #     anymore.
  |
  | if __name__ == "__main__": # <·· module self-check. true when module 
  |     custom_init()          #     is executed as python -m module (vs
  |     sys.exit()             #     imported into another module)
  |                            #     __name__ === script/module when imported.
  |
  | NOTE: A Similar effect for python packages uses the main.py script:
  | my_package/main.py
  | ...
  ```
